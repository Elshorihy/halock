# الاختبارات اليدوية — HALOCK

> قائمة سيناريوهات التحقق اليدوي (spec §14–15 + تكامل الراوتر). طريقة التنفيذ: `npm run dev` أو النشر، ثم اتبع السيناريوهات.

## أ) حالات الفشل والاسترجاع (10 سيناريوهات مطلوبة)

| # | السيناريو | خطوات التنفيذ | النتيجة المتوقعة (المُتحقَّق منها في الكود) |
|---|---|---|---|
| 1 | انقطاع الإنترنت أثناء الجلسة | ابدأ جلسة ← اقطع الواي فاي | المؤقت يستمر (timestamps) ← شارة offline ظاهرة ← عند العودة العداد صحيح |
| 2 | تحديث الصفحة أثناء الجلسة | ابدأ جلسة ← F5 | الجلسة تعود من التخزين ← الوقت المتبقي مطابق تمامًا (لا إعادة ضبط) |
| 3 | إغلاق المتصفح | ابدأ جلسة ← أغلق المتصفح كاملًا | لا شيء يُفقد |
| 4 | إعادة فتح الموقع | افتح الموقع بعد الإغلاق | شاشة الجلسة الجارية أو شاشة الاسترداد إن كان الوقت انتهى |
| 5 | فشل الاتصال بالراوتر | صفحة الراوتر ← اختبار الحجب مع اتصال متقطع | «تعذر التحقق من حالة الحجب» أو «لا يوجد اتصال بالإنترنت» — لا نجاح كاذب |
| 6 | فشل تطبيق قواعد الحجب | الوضع اليدوي ← ابدأ جلسة دون تنفيذ الخطوات | الحالة: «الحجب يدوي — لم يُنفَّذ تلقائيًا» (لا ادعاء نجاح) |
| 7 | فشل استعادة إعدادات الراوتر | دليل الاستعادة يظهر دائمًا في صفحة الراوتر | خطوات الاستعادة متاحة + سجل العملية يُسجَّل |
| 8 | انتهاء الجلسة والموقع مغلق | ابدأ جلسة قصيرة ← أغلق المتصفح حتى تنتهي | عند العودة: شاشة «وجدنا جلسة غير مكتملة» ← حفظ مرة واحدة فقط |
| 9 | تسجيل الدخول من جهاز آخر | سجّل دخولًا ثم استخدم التوكن نفسه على جهازين | كلاهما يعمل (جلسات متعددة مسموحة) — البيانات موحدة ومحمية |
| 10 | بدء جلستين معًا | اضغط «بدء» مرتين سريعًا / في تبويبين | الرسالة: «يوجد جلسة تركيز نشطة بالفعل» + الخادم يرفض 409 |

### نتائج التنفيذ الفعلي (مُختبَرة آليًا حيث أمكن)

- السيناريوهات 2/3/4/6/8/10 مغطاة باختبارات آلية (`tests/session.test.ts`, `tests/router-provider.test.ts`, `tests/timer.test.ts`).
- السيناريوهات 1/5/7/9 سلوكها مضمَّن في الكود (مؤشر الاتصال، رسائل «تعذر التحقق»، دليل الاستعادة، توكنات متعددة) وتُتحقق يدويًا على المتصفح/الجهاز.

## ب) تكامل الراوتر (اختبار يدوي كامل — Huawei DN8245V)

1. **قبل أي تعديل**: خذ صورة شاشة لصفحة Parental Control.
2. افتح HALOCK ← صفحة الراوتر ← الوضع **يدوي**.
3. املأ «الجهاز المستهدف» ورابط الراوتر ← احفظ.
4. نفّذ الخطوات العشر في قائمة التفاعل وعلّم كل خطوة عند إتمامها.
5. عند الخطوة 9: افتح موقعًا محجوبًا من الجهاز المستهدف → يجب أن يُمنع.
6. في HALOCK: زر «اختبار الحجب» مع نفس الموقع:
   - متصل بالإنترنت والمحجوب → «يبدو أن الموقع محجوبًا (تعذر الاتصال)».
   - غير محجوب → «يبدو أن الموقع متاحًا».
   - غموض → «تعذر التحقق من حالة الحجب».
7. ابدأ جلسة تركيز مرتبطة بنفس القائمة ← تحقق أن شاشة التأكيد تعرض:
   - المدة، المهمة، المواقع، طريقة الحجب، حالة الراوتر.
   - ملاحظة صريحة: لم يتم تغيير إعدادات الراوتر تلقائيًا.
8. انتظر انتهاء الجلسة ← احفظها ← تحقق من:
   - ظهورها في الإحصائيات وسجل الجلسات.
   - سجل جديد في «سجل عمليات الراوتر» (session-start / session-end).
9. الاستعادة: احذف قواعد HALOCK من URL Address Table يدويًا ← تأكد من عودة الإنترنت.
10. **الوضع التلقائي**: اختره ← يجب أن يظهر «غير مدعوم حاليًا — يحتاج إلى تحقق من Firmware» + المتطلبات الستة غير الملباة، و«اختبار» يُرجع `not-supported` ويسجَّل ذلك.

## ج) اختبارات التوافق والأداء (يدوية)

| المنصة | ما يُتحقق منه |
|---|---|
| Android Chrome | الأزرار ≥44px، القائمة السفلية، المؤقت بعد العودة من الخلفية |
| Samsung Internet | نفس ما سبق + التثبيت PWA |
| iOS Safari | التوقيت، safe-area، عدم الاعتماد على hover |
| جهاز لوحي | التخطيط (grid) بمقاس متوسط |
| حاسوب (Chrome/Firefox/Edge) | التنقل العلوي، النوافذ، التصدير/الاستيراد |
| شاشة صغيرة (320px) | لا ت overflow، النصوص مقروءة |
| `prefers-reduced-motion` | إيقاف الحركات تلقائيًا (CSS + Framer Motion) |
| ضعف الشبكة | العمل المحلي بلا انقطاع، رسائل صريحة |
